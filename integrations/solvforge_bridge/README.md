# SolvForge MD ↔ MoDy Analyse Integration Bridge

`SolvForge MD` and `MoDy Analyse` operate as **two decoupled repositories sharing a file/JSON contract**:

```text
[SolvForge MD Web/Desktop App]
        │
        │  Exports: Run Input Package + metadata.json + project_manifest.json
        ▼
[GROMACS Execution (Workstation / HPC)]
        │  Produces: 04_prod/prod.tpr, prod.xtc, analysis/thermo.xvg, stress.xvg, rdf/*.xvg
        ▼
[MoDy Analyse Compute Engine (Python CLI)]
        │  Produces: results/tables/*.csv, results/figures/*, cluster/orca/multiwfn artifacts
        ▼
[Optional Exchange Back to SolvForge UI] *(planned JSON summary bundle)*
```

## Expected Run Directory Layout

`mody_analyse.core.discovery.discover_runs()` expects each simulation replicate directory matching `run_glob` to contain:

- `metadata.json` (generated by SolvForge MD or created manually matching `run_metadata.schema.json`)
- `00_input/topol.top` and included `.itp` topology files
- `04_prod/prod.tpr`, `04_prod/prod.xtc` (plus optional `prod.edr`, `prod.log`)
- `analysis/thermo.xvg` (Temperature, Density, Potential Energy, Pressure, Box/Volume)
- `analysis/stress.xvg` *(required for Green–Kubo viscosity if stress tensor components are not in `thermo.xvg`)*
- `analysis/rdf/rdf_*.xvg` (center-of-mass RDFs) and optional `analysis/blocks/rdf_*.xvg` (block convergence checks)
